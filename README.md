## 1. 项目简介

VisionSoul 是一个具有视觉感知与动态人格模拟能力的多模态 AI 交互系统。

系统允许用户通过短视频、图片和文字提问。当前主线转向音视频结合的日常实用助手：提取信息、区分声音与画面依据、提供可回看的时间点。首个具体场景为课堂代码视频排错，结合可读源码、终端错误与用户目标给出修改提示，使用方式见[课堂代码视频排错](docs/课堂代码视频排错.md)。

当前主界面分为“工作解析”和“角色对话”：前者客观解答、仅保留任务话题上下文，后者使用自由人格设定及已确认角色记忆；两边的话题和历史独立。旧记录保留在未分类列表，需明确归类后继续，详见第30节。

2026-11-10 根据用户决定，优先打磨日常使用，人格占比后续再决定。2026-11-09 人物设定已改为自由文本创作：名称、背景和性格都可重新编写，直接粘贴原文，不再要求JSON模板或固定性格。仍只使用一张角色卡，保留原有图片、聊天和记忆功能；角色用法见第19节，前面P014/P015的流程作为历史记录。

## 7. 图片模块约定

- 上传接口：`POST /api/images`，表单文件字段名为 `file`。
- 预览接口：`GET /api/images/{image_id}`。
- 支持 JPG、PNG、WebP 静态图片；默认原文件及处理后文件均不超过 10 MiB（10,485,760 字节）。
- 默认单边不超过 8192 像素、总像素不超过 2000 万；不支持动图和 GIF。
- 根据实际内容解码校验，不信任文件后缀或浏览器声明的类型。有效图片即使文件名错误也可以上传。
- 自动纠正 EXIF 方向并重新编码，移除 EXIF、位置等元数据；JPEG/WebP 重新编码可能轻微改变画质，不保留原始文件。
- 图片使用随机标识保存到 `backend/storage/images/`，不采用用户文件名，不进入 Git。
- 完整请求体上限为图片大小上限加 64 KiB，在解析表单前检查，包括分块传输请求。
- 返回值中的 `size_bytes`、`width`、`height` 描述处理后图片，不包含本地磁盘路径。

可在 `backend/.env` 中覆盖 `IMAGE_STORAGE_DIR`、`UPLOAD_MAX_BYTES`、`IMAGE_MAX_PIXELS`、`IMAGE_MAX_DIMENSION`。
默认存储目录固定在 backend 下，不随启动目录改变。若覆盖存储目录，请使用绝对路径。

错误码：空文件/无效图片/损坏图片/动图为 400；大小或像素超限为 413；不支持的实际图片格式为 415；缺少文件字段为 422；图片不存在为 404。
存储写入失败为 500，客户端不会收到服务器的磁盘路径。

当前用于本机开发，尚未实现账号和图片访问权限；预览链接凭随机标识访问。对外部署前需补充用户隔离与访问控制。

## 9. DeepSeek 图片理解

用户已选定 DeepSeek V4.1 Flash（10 月 17 日更新版）。官方当前 API 模型名为 `deepseek-flash`，这个名称会随服务商更新，不代表永久锁定 1017 权重。
后端根据图片标识读取已上传图片，结合用户文字调用官方 `https://api.deepseek.com/chat/completions`。
图片理解提供单次观察；“伙伴对话”模式使用同一固定人格，可以结合一张图片连续追问。

本机 `backend/.env` 已创建为空密钥模板；如果在其他机器使用，可以复制 `backend/.env.example` 为 `backend/.env`。
用编辑器打开 `.env`，在 `DEEPSEEK_API_KEY=` 后填入真实密钥并保存，然后重启后端。
配置路径固定在 backend 下；无论在项目根目录还是 backend 目录启动，均读取同一个文件。
`.env` 被 Git 忽略，示例文件只有空密钥，可以进入 Git。

- `GET /api/vision/status`：只检查本机是否填写密钥，不调用 DeepSeek、不验证密钥或余额，返回内容不包含密钥。
- `POST /api/vision/analyze`：读取已上传图片并调用 DeepSeek，发送图片及问题，产生账户 API 用量。

在 `/docs` 中先上传图片，然后把返回的 `image_id` 填入图片理解接口，例如：

```json
{
  "image_id": "替换为上传成功返回的32位标识",
  "question": "这张照片里有什么？请描述主要场景。"
}
```

成功返回 `answer`、服务商返回的 `model`、`usage`（服务商提供的 token 计数，可能为空）和 `truncated`。
`truncated=true` 表示回复达到输出上限被截断。

默认配置以控制开销为目标：图片 `detail=low`、关闭思考模式、输出最多 512 token，单次调用不自动重试。
low 会降低输入图像细节；辨认小字或细节时可在 `.env` 中将 `DEEPSEEK_IMAGE_DETAIL` 改为 `high`，并重启服务。
`DEEPSEEK_MAX_TOKENS` 可在 32 至 2048 之间调整，`DEEPSEEK_TIMEOUT_SECONDS` 默认为 45 秒。
超时是网络阶段的等待上限，不代表整个请求必定在 45 秒内结束。

图片标识错误/问题为空或超长为 422，图片不存在为 404，密钥未填/认证失败/余额不足/限流为 503，网络或上游结果异常为 502，等待模型超时为 504。
错误消息不返回服务商原始响应或密钥，不会通过客户端指定任意 API 地址或本地文件路径。

已通过 22 项自动验证，并完成一次真实 API 调用：成功识别简单几何测试图，返回 HTTP 200。
详细联调结果与用量记录见 P004。当前是单次图片理解；连续对话、人格和记忆将在后续模块实现。

官方参考：[更新记录](https://api-docs.deepseek.com/updates/)、[视觉输入说明](https://api-docs.deepseek.com/guides/vision/)。

## 11. 简洁图片工作台

日常使用请打开后端地址下的 `/app/`，本轮运行地址为 http://127.0.0.1:8765/app/。
接口文档 `/docs` 保留用于开发调试，顶部也提供工作台入口。

1. 选择或拖入图片。单张图片自动上传并预览，编号由页面自动绑定。
2. 填写问题，点击“开始分析”。只有这一步调用 DeepSeek 并产生模型用量。
3. 在右侧直接查看回复和本次用量，不需要展开多个接口。

本版只分析单张图片。一次选择多张时，只显示本地缩略图，提示“目前只能分析单个图像”，不上传这些多选图片，也不调用模型。

分析过程中锁定图片和问题，重复点击不会并发发送相同请求；快速换图时也不会套用旧图片编号。
清空操作清除当前页面的选择和回复，不删除后端此前保存的图片。

桌面采用左右两栏，回复较长时仅在结果区滚动；窄屏采用上下布局。
当前保持单图限制；固定人格及会话上下文见下方“伙伴对话”。基础记忆卡见第 17 节，多图理解仍留待后续。

## 13. 小灵：固定人格与连续对话

工作台右上角可切换“图片理解”和“伙伴对话”。固定伙伴暂用名“小灵”，按用户选择采用活泼俏皮、轻度幽默的风格。
遇到严肃或失落话题时，规则要求先认真倾听、减少玩笑；身份与情绪表达保持 AI 透明性。
共用性格位于 `backend/app/prompts/persona.md`；普通聊天与单图理解再叠加 `companion.md`，视频再叠加 `video.md`。由服务端组合并加入上下文，前端不能提交其他系统角色来替换。当前人格规则版本为 `xiaoling-v2`。
当前情境化情绪通过提示规则调整表达，未实现独立情绪评分或情绪状态机。

使用方式：

1. 点击“伙伴对话”，直接输入文字即可聊天，不强制上传图片。
2. 如需聊图片，在左侧选择一张，上传就绪后发送消息；图片编号仍自动关联。
3. 在同一个话题继续提问，后端会带入最近的完整问答。
4. 点击“新话题”开启独立聊天；下拉框可切换本机最近二十个话题。
5. 刷新或重启服务后，再进入“伙伴对话”可恢复最近话题，不会重新调用模型。

每段话题最多关联一张图片。已有图片的话题换成另一张时，下一次发送会自动开启新话题；旧话题保留在近期列表。
清空左侧待选图片不会删除已经发进对话的图片消息，同一话题仍可继续围绕先前图片追问。
多选图片或单图尚未上传成功时阻止发送，避免只发送文字而遗漏用户预期中的图片。

后端将聊天文字、图片编号、已完成请求结果保存在 `backend/storage/chat.sqlite3`，不保存 API Key 或图片的 Base64 内容。
该目录本来就被 Git 忽略。浏览器本地只保存最近话题编号，实际记录在 SQLite。
新话题不会删除旧话题；目前的历史列表最多显示最近二十段，每段页面最多读取最近 200 条消息，完整记录仍在本机。
当前持久化内容是聊天记录；用户偏好提取、跨话题记忆、遗忘管理属于后续模块。

为控制用量，每次最多参考最近 6 轮完整问答，历史文字预算默认 12000 字符，并继续使用 low 图片精度、关闭思考模式、最多 512 输出 token。
一段话题中的图片每轮只提供一次，不随历史消息重复叠加；含图片的追问仍会把该图交给模型。
`CHAT_CONTEXT_TURNS` 和 `CHAT_CONTEXT_CHARS` 可在后端 `.env` 调整。

发送不自动重试。前端锁定发送和切换操作，服务端对同一话题并发返回 409；已经成功入库的同一 request_id 可恢复原回复，不再次调用模型。
此请求锁针对当前本机单进程运行方式；本阶段不配置多 worker。若上游超时或最终入库失败，无法保证上游没有产生用量，用户显式重试仍需谨慎。
当前只服务于本机开发，没有账号隔离；对外部署前需完成访问控制。

新增 API：

- `GET /api/chat/status`：固定伙伴信息、上下文窗口与密钥填写状态，不调用模型。
- `GET /api/chat/conversations`：本机近期话题。
- `GET /api/chat/conversations/{conversation_id}`：恢复话题。
- `POST /api/chat/messages`：发送用户消息；首次 conversation_id 留空，request_id 由前端自动生成。

验证结果：后端 37 项、前端 16 项，共 53 项自动验证通过；真实两轮图文对话及服务重启后的四条消息恢复成功，详见 P008。
日常启动仍使用上节 PyCharm 命令。自动工具启动前应同时确认图片目录和聊天数据库所在目录可写。

官方参考：[DeepSeek 多轮对话](https://api-docs.deepseek.com/guides/multi_round_chat/)、[图片输入](https://api-docs.deepseek.com/guides/vision/)。

## 14. 当前主线：短视频观察与小灵回应

1. 启动后打开 `/app/`，默认进入“视频观察”。
2. 选择一个 H.264 编码的 MP4，不超过 30 秒，默认不超过 50 MiB、4K 分辨率、60 FPS。10 秒等更短的视频也可以上传，不设 20 秒最低时长。常见手机 HEVC/H.265 视频暂不接收，需要先导出为 H.264 MP4。
3. 上传后本地解码、按1秒采样并自动绑定编号，同时用本机语音模型转写对白。这一步不调用付费API；视频和原始音频不上传给新的语音服务商。
4. 在右侧输入想说的话，例如“嘿，我今天去了西湖玩，你看看这湖水怎么样”，点击“分享并对话”。首次无可用观察时，一次请求同时理解画面和回应配文；已有观察时只用文字资料接话。
5. 在同一输入框继续追问。模型参考本话题首次分享、视频观察和最近 6 轮完整问答，追问不会重传视频截图。
6. 点击左侧“观察依据”展开关键词、概述和时间截图，点击截图可以定位视频。观察依据默认收起，右侧仅在聊天区内滚动。
7. 话题和完整问答保存本机；刷新或重启后恢复，不调用模型。下拉框可切换近期视频话题。每次主动发送新的消息仍可能产生用量；已完成的同一请求可恢复原回复。
8. 更换另一个视频时，下一次发送会开启新话题，原话题保留；点击“新话题”也可重新开始。一个话题关联一段视频，图片聊天继续在“伙伴对话”使用。

### 省量与模块划分

- 采用 PyAV 的 Windows 二进制包（内含 FFmpeg 库），无需额外安装系统 FFmpeg；依赖已固定为 `av==19.0.2`。
- `video_extract.py` 在独立子进程里处理本地视频，`audio_extract.py` 单独受限处理音轨和本机转写；有时长、像素、解码数量及处理超时限制，外部媒体引用禁用。
- 当前每1秒选择一个实际画面，并额外保留不同的末帧；10/20/30秒定帧率视频通常分别采样11/21/31次，实际数量受源帧时间影响。低帧率不重复源帧凑数。像素完全相同的画面（包括间隔后再次出现）只保存和发送一次，全部采样时间仍保留。不采用激进的近似去重，不以30张截断尾帧。旧半秒记录最多61张仍可恢复。
- 概览截图最长边 768 像素，上传时额外保留最长边 1280 像素的细节图。显式“细看并比对”按质量、内容差异和时间覆盖选择最多4张，再从原视频按需提取最长边1920像素的高清图，不放大小尺寸原画面；其余仍使用 `low`，保持原采样覆盖。详见第22节。远景小字、细叶仍可能无法辨认。
- 所有保留截图合为一次请求，关闭思考模式，结构化输出上限 1600 token，最多 8 条核心观察；只合并关键词、描述和不确定性都相同的相邻重复观察，不因同为“树木”就删掉新角度的特征。上限不是实际用量，也不是金额。
- `videos.py` 负责存储、一次分析和成功缓存；共用现有 `deepseek.py`，未另建一套模型 SDK。
- 缓存按视频内容、抽帧配置、模型配置、提示版本和输出预算区分；模型提示或相关配置变化后可能需要重新分析。旧版每 3 秒采样的视频会提示重新选择，不能冒充已完成新策略采样；原文件与旧结果保留。缓存损坏不会静默触发重新付费。
- 上传/抽帧与分析各有本机单进程并发锁；前端锁定重复操作。不自动重试。超时、结构化结果无效、保存失败等情况仍可能已有上游用量，显式重试需留意提示。
- `video-workflow.mjs` 管理上传与恢复；`VideoWorkspace.jsx` 负责播放器和折叠观察依据；`VideoChatPanel.jsx` 负责视频配文及连续问答。与图片聊天共用 `chat-workflow.mjs`，使用独立的话题列表和最近话题编号。

### 数据与边界

视频原文件、采样图、抽帧清单和分析结果保存到 `backend/storage/videos/`，已被 storage 规则排除，不进入 Git。原始MP4、提取的audio.wav、本机模型权重和audio.json转写留在本机；发给DeepSeek的是静态图、转写文字及时间候选，不传原始音轨给新服务。视频问答、首次分享、对白和音画依据快照保存在 `backend/storage/chat.sqlite3`，没有图片 Base64 或密钥。浏览器本地只保存最近视频和话题编号。清空页面不会删除后端视频或聊天记录。

当前不是逐帧完整理解，不精确追踪动作和起止边界，不保证识别全部事物。音频首版只转写中文对白，结合画面与配文理解目的，没有声音语调/情绪识别。音画时间候选不是语义验证；讲话者不一定是用户。结果只展示有来源的时间；不确定时允许“水面”“疑似月亮”，不能强行编出湖名、日期或用户经历。普通追问基于保存的观察与对白，未保存的细节无法保证回答；可显式点击“细看并比对”重新读取画面（第 20 节）。用户说过“西湖”时可以据此交流，但不能把它当成模型从画面验证的地点。

话题上下文保留首次分享＋最近 6 轮问答；历史文字部分受字符预算裁剪，固定视频观察和首次分享保留。完整消息仍存本机，但不保证模型每轮读取全部历史；较早的补充或更正超出窗口时可能需要用户再次说明。现在可额外参考用户已确认的基础记忆卡（第 17 节）；长期关系系统仍未实现。

当前只适用于本机、单用户、单后端进程。对外部署前需增加访问控制、磁盘配额和数据删除机制。

API：

- `GET /api/videos/status`：限制和密钥填写状态，不访问模型。
- `POST /api/videos`：表单字段 `file`，上传并本地抽帧，不访问模型。
- `POST /api/videos/analyze`：JSON 字段 `video_id`，首次调用模型，有成功缓存时直接返回。
- `GET /api/videos/{video_id}`：元信息、截图和匹配当前配置的已有结果。
- `GET /api/videos/{video_id}/file`：本机视频，支持 Range 定位播放。
- `GET /api/videos/{video_id}/frames/{index}`：对应采样截图。
- `POST /api/chat/messages`：可增加 `video_id`，与 `message` 一起开启视频话题；`image_id` 和 `video_id` 不能同时填写。同话题后续可只给 `conversation_id` 和新消息。
- `GET /api/chat/conversations?kind=video`：近期视频话题；默认列表只含纯文字/图片话题。

## 15. 小灵的表达完善（P012）

性格维持“活泼俏皮，轻度幽默”，补充稳定的表达习惯：留意一个具体细节、偶尔用贴切的比喻、普通事情平常接话，减少机械夸奖、固定口头禅和每次结尾反问。遇到失落或严肃语境认真倾听，不拿困难开玩笑，也不替用户加重负面措辞。

视频的 `summary` 负责事实概述，`reply` 用一两句回应用户的分享，避免再次复述整段视频。没有地点、日期或用户心情的依据时，不为表现亲近而编造这些信息。情境化表达仍由模型提示控制，没有新增情绪评分或独立情绪状态机。

共享性格只在每次请求中加入一份，视频继续单次请求生成观察和回应，不新增“先分析、再润色”的调用。人格提示更新会使视频分析缓存指纹变化；旧结果仍留在本机，不自动重算，需要用户手动点击观察才可能产生新用量。聊天中的旧消息与已完成请求缓存也不重写。

本轮后端 56 项通过；另进行了 3 次真实样例验证（小成果、失落语境、自制插画视频），共 2928 token。视频样例在重启后成功读取缓存，没有再次调用模型。少量样例不能证明所有情境下的人格稳定性，仍需用户体验反馈。实际输出、措辞微调与限制见 `prompts/P012_统一小灵人格与自然回应.md`。

## 17. 小灵人格卡与基础记忆卡（P014 历史实现）

主界面右上角点击“角色与记忆”，或直接访问 `/app/#/roles`。左侧只有小灵，包含“人格卡”和“记忆卡”两个栏目。数据按角色编号分别存储，为未来多张卡预留位置；本项目没有添加、启用其他角色或切换角色的入口。

人格卡可以直接编辑身份、性格、说话方式、背景、兴趣与相处方式，也可以通过左侧讨论逐步整理。讨论结果只保存为草稿；“预览回应”使用当前草稿进行一次隔离试说，不读取或写入正式聊天记忆。点击“保存并生效”后，新消息立即使用新设定，无需重启；“只保存草稿”不影响正在使用的版本。历史版本可载入草稿后再保存。小灵的 AI 身份和不编造用户经历的边界继续保留。

角色卡、版本、设定讨论与记忆条目保存在 `backend/storage/roles.sqlite3`。默认路径从聊天数据库目录推导，也可设置 `ROLE_DATABASE_PATH` 为绝对路径。未发布新卡时继续使用原有小灵提示。已完成的旧消息和请求缓存不重写；发布角色卡会影响视频观察缓存指纹，但不会自动重新调用模型。

记忆卡支持手动添加偏好/用户信息，也支持选择近期话题，点击“整理话题记忆”。模型生成的话题摘要与偏好候选均为“待确认”；候选偏好必须附带所选用户消息的逐字原话，助手推断和无有效出处的条目会被排除。确认后才用于后续对话，也可编辑、暂停或移除。手动明确添加的记忆直接启用。移除记忆卡不删除原聊天，近期问答仍可能包含相同内容。

为控制开销，进入页面、手动编辑、保存、切换栏目和刷新不调用模型；讨论、预览、整理各由点击触发，均不自动重试。记忆整理最多读取最近 24 条消息、6000 字符及该话题上一份已确认摘要，同一段未更新的消息复用结果。运行时从最近更新的 100 条记忆中选择最多 8 条已确认信息，加至多 1 份本话题摘要，总量约 1000 字符；采用轻量文字匹配，没有向量检索或全历史读取。摘要只用于来源话题，已确认的偏好/用户信息可用于其他话题。

新增 API 前缀为 `/api/roles/xiaoling`：

- `GET` 前缀本身、`/sources`、`/memories`：角色、近期话题、记忆列表。
- `PUT /draft`、`POST /publish`：保存草稿或生效；使用版本号避免覆盖过期修改。
- `POST /discuss`、`/preview`、`/extract`：显式调用模型；成功请求编号可恢复结果。
- `POST /memories`、`PATCH /memories/{memory_id}`、`DELETE /memories/{memory_id}`：手动新增、修改/确认/暂停、移除条目。

P014 阶段后端 75 项、前端 35 项验证通过，生产构建成功。真实验证共 3 次模型调用，1515 token；再次整理复用了结果。临时测试话题及候选条目已清理，原有聊天记录与操作前备份逐条一致。保留一份基于既定性格的讨论草稿供用户继续修改，尚未替用户发布。具体实际 Prompt、文件与验证记录见 `prompts/P014_角色管理与记忆卡.md`。

## 19. 从零创作自由人物（P016，当前方式）

刷新 `/app/#/roles`，现在只有“角色名称”和一块“自由人物设定”大文本框。直接粘贴与其他 AI 讨论好的最终设定，也可自己写；普通段落、Markdown、世界观和对话例子都按原文保存，不要求字段、JSON、章节或性格模板。“从空白开始”清空当前编辑内容，保存前不改变已存数据。

“保存草稿”不会影响正式对话；“保存并生效”后，后续图片、文字、视频回应使用新人物设定。自由模式不再加入旧版的“活泼俏皮、轻度幽默”及固定说话习惯。角色显示名字也可修改，内部编号仍保留为 `xiaoling` 以兼容现有数据，没有新增多角色切换。试说和历史版本收在可展开区域；记忆卡管理继续可用。体验新人物时可新建话题，避免把旧话题里的交谈当作新人物的经历。

工具链装在 backend/storage/sandbox-runtime/c 下（默认 Zig 0.17.1，约 360 MB，不进 Git），安装脚本校验 SHA-256。可在 backend/.env 设置 C_SANDBOX_ENABLED=false 或 C_SANDBOX_AUTO_REPAIR=false，也可用 C_SANDBOX_COMPILER 指向其他 zig.exe。Visual Studio 打开与沙箱试跑并行存在：沙箱负责判定对错，VS 供你自己运行。详见 [P048](prompts/P048_C语言隔离编译与断言验收.md)。
