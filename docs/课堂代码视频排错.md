# 课堂代码视频排错 · 首版

目标：用一段短视频同时展示源码、终端错误及你的说明，获得有画面依据的可能原因和修改提示。当前用Python受控样例验证；真实课堂拍屏效果仍需实测。

## 怎么用

1. 录制约15—25秒H.264 MP4，最长仍为30秒。先停稳展示出错调用附近的源码，再展示同一次运行的完整错误结尾和行号。把字体放大，保留清楚的变量名、大小写和缩进，避免快速拖动窗口。
2. 上传视频，配文写明“预期做什么、实际发生什么”。也可以在视频里口述背景，例如：“我想把两个数字相加，但这里报错了。”点击 **代码排错**。
3. 在左侧 **排错** 查看可读错误、可能原因、最小修改步骤、建议片段及需要补充的信息。点击“回看”定位源码/终端出现的时间；这些时间不是代码行号。
4. 普通“发送消息”可继续追问，复用这个话题的已保存文字资料。修改后出现新错误，可粘贴新报错或上传新视频；程序不会自行读取你电脑上的源文件。

点击代码排错会显式重新读取画面，一次模型请求，最多4张高清，其余概览保持；本地抽帧/选帧不额外调用模型。普通追问不自动重传图片。只有清晰可读时才可能定位到具体变量或行号，模糊时会请求补拍或粘贴文本。

## 输出如何理解

- “有依据的可能原因”仍需要你核对并运行验证；建议片段是供你修改的文字，不自动执行或写入课程项目。
- 源码和报错分开引用，避免混合不同文件/运行结果。画面行号只有在可见时填写，图号与视频时间不当作代码行号。
- 不清楚的字符、路径、变量名和缩进不应靠猜补全；缺少依赖版本、输入或完整调用时，会列出需要补充的内容。
- 音频提供背景，视觉证据提供代码和错误原文。无关讲话不应变成代码错误的证明；“人物在讲话”不代表对白内容得到画面验证。

## 转写与记忆

原始转写保持不变。重复循环或文字密度与时长明显不符的片段会标为待校对，分析和追问使用遮蔽副本，时间编号保留；自动附加依据也会提示回听，不把异常文字当原话引用。打开“校对白”核对后，用户校对白优先使用。

这只是启发式检查，不是语音正确率或专业置信度。专名误听未必能检测，真实重复讲话也可能误报，原文仍可回听/校对。`content_visible`是模型对可见内容的声明，程序可对缺失声明、异常转写或明显矛盾理由降为待确认，但不能自动证明语义正确。

排错结构和文字建议保存在本机话题中；校对白后旧报告标待更新，后续模型不沿用过期诊断。已保存的历史消息保留。第三方模型及数据去向仍见页面底部“模型与数据说明”。

## 已验证与局限

后端159项、前端57项及生产构建通过；真实API分别验证了变量名错误、类型错误和模糊信息不足。测试是程序生成的屏幕素材，不是课堂实拍，不能据此宣称实际拍屏准确率。1秒采样可能错过短暂提示，反光、斜拍、过小字体和复杂工程上下文仍会影响结果。样例及原始回执见`datasets/code_debug_eval/`。
