# P041 编程术语复识别防误判

2026-11-11。Codex 修改本机复识别校验，使用原有 faster-whisper Small 和公开参考音轨进行对照。无 DeepSeek 请求。

> 下一步目标：用未参与调参的人工字幕样本优先验证会改变答案的专业术语（如 C 语言）的命中率、误判与耗时，方言词仅在影响任务且无法确认时追问。</p>按这个目标进行下一步调试优化。

`audio_extract.py` 保留 C++ 和 C# 的符号，也能核对「C 加加」「C 井号」等口述写法。已有明确语言时，在同一窗口复识别不得换成别的语言或删掉语言约束。相邻分段的语言可用于限制新候选引入的术语。原始转写继续保存，复识别仍最多一次、最长六秒。`audio_evidence.py` 更新版本，重新上传进入新版。`audio.md` 明确配文优先、冲突时核对画面，关键细节仍不清楚才追问。`test_audio_evidence.py` 覆盖符号、口述别名、相邻分段和候选换语言。

## 对照结果

基线为 `f15488c`。公开样本未用于调参，独立于之前手机视频。使用同一台机器、同一模型和四个 CPU 线程；暖模型上两版共享首次解码，统计首次解码加各自的复核时间，不含下载或模型加载。命中指预先指定的参考术语在原转写或候选中出现，忽略大小写和标点空格，保留加号和井号。编程语言误报只统计监测列表中的 C、C++、C#、Python、Java、JavaScript 和 Rust。

| 样本 | 参考词 | 基线 → 新版 | 新版秒数 |
| --- | --- | --- | ---: |
| 李宏毅课堂，字幕行 2 | AI Agent | 漏 → 漏 | 1.70 |
| 李宏毅课堂，字幕行 8 | Context Engineering | 漏 → 漏 | 1.61 |
| 李宏毅课堂，字幕行 20 | OpenClaw | 漏 → 漏 | 1.53 |
| 李宏毅课堂，字幕行 36 | prompt | 漏 → 漏 | 1.94 |

| WenetSpeech test-meeting 行 92 | 点餐软件 | 中 → 中 | 2.83 |

公开音轨 1/6 → 1/6，监测的编程语言误报 0 → 0；仍有 OpenClaw 被识别为 Open Cloud、prompt 被识别为 Pump 等误听。前四行采用发布的 VTT 字幕，未独立核实其制作方式。后两行使用人工标注的 WenetSpeech 测试集原始转写字段。公开样本没有覆盖 C++/C# 口述，规则防替换用模拟模型验证，不能作为这两个术语的实录准确率。

两段旧手机视频作为回归对照，已确认的「C 语言」「补全」三次命中均保留，分别约 4.59 和 4.43 秒。后端 219 项测试通过，网页已加载 v4。临时评测音轨不提交。
