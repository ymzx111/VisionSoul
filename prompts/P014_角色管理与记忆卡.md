# P014：小灵人格卡与有来源的记忆卡

日期：2026-11-08

## 1. 用户实际要求与范围

> 好，那先来做一下角色卡，我希望你能做一个后台样子的界面，把角色的性格设置这些放到这里面，然后从主界面设置一个小窗口可以切换到这个角色页面。对于这个角色卡，我希望可以创建一个人格卡，通过我们对话来确定她基础的性格这些方面，之后为她添加一张记忆卡，用来存储记忆整理上下文。

开始实施的补充要求：

> 先创建小灵这一张卡，如果可以你可以建一个可以保留多张人格卡的渠道，之后可以添加新角色。不过我希望目前这个项目到结束，只使用小灵一个角色可以，但是我还是希望你保留多人格卡的渠道，用于后续可能的拓展。请你开始工作吧.

保留既定“活泼俏皮，轻度幽默”的性格方向。本轮实现设置页面、可讨论的人格草稿、隔离试说、发布版本与基础记忆管理；头像美术、多角色切换、复杂关系系统不纳入本轮。

工具：Codex 桌面端在现有仓库直接实现和测试；当前工具未提供精确的编码模型版本标识，不猜测型号。应用模型复用本机已配置的 DeepSeek 官方客户端；真实预览响应模型为 `deepseek-flash`。未新增 SDK 或依赖，未读取或输出密钥值。

## 2. 实际设计与运行时 Prompt

- 新 SQLite 表按 `role_id` 存卡片、发布版本、设定讨论、模型请求结果与记忆。只有 `xiaoling` 启用，预留的 `create_reserved` 存储扩展点默认禁用其他卡；没有新增角色或切换接口。
- 正式设定和草稿分别保存。讨论只更新草稿，手动修改也可只存草稿。发布后后续消息动态加载，不需重启。版本冲突返回 409，不覆盖别处已保存的内容。
- 预览使用当前草稿单独试说，不读取正式记忆，不把测试消息写入聊天或用户记忆。讨论记录也不进入用户聊天。
- 角色编排实际系统提示完整保存在 `backend/app/prompts/role_builder.md`：保持未讨论字段、每次一个关键问题、不擅自创造身世、固定小灵名字与 AI 身份、返回完整 JSON 草稿。
- 记忆提取实际系统提示完整保存在 `backend/app/prompts/memory_extract.md`：只提取明确用户信息、引用用户消息 ID 与逐字原话、摘要和最多四条候选，不把助手猜测、假设或角色设定当成用户事实。
- 发布后的角色通过 `compile_profile` 编译，继续加入不编造用户经历的边界和既有 `companion.md`；未发布时沿用原 `persona.md`。图片理解、文字/图片聊天、视频观察与视频问答复用同一份生效设定。
- 记忆模型结果先待确认。服务端验证候选所引用消息确实是 user，原文片段确实存在，再存卡；这只能校验出处，不能证明推断一定正确，因此仍需用户审阅。
- 记忆卡可编辑、确认、暂停、移除。手动明确添加的内容直接确认。原始聊天与记忆条目分别保存，移除卡片不删除原消息。

## 3. 省量与边界

进入页面、切换栏目、手动编辑/保存、读历史、确认/暂停均不调用模型。角色讨论最多使用最近八条设定消息，输出上限 1000 token；预览上限 220 token；记忆整理上限 1200 token。均关闭自动重试，成功请求可用相同编号恢复。

记忆整理读取最近最多 24 条消息、6000 字符和本话题上一份已确认摘要。同一来源话题、同一覆盖消息编号直接复用结果，不再调用模型。不会每轮聊天自动提取记忆；移除候选后，对同一批未变化内容也不会重建该候选。

对话从最近更新的 100 条卡片中选择已确认条目，优先轻量文字匹配，最多八条偏好/事实及一份本话题摘要，总量约 1000 字符。摘要不带入其他话题；确认的用户信息可跨话题使用。这是基础筛选，没有向量库、自动矛盾消解或无限上下文。近期聊天仍保留最近六轮等既有窗口，不能保证读取全部历史。

发布设定会改变视频提示缓存指纹，但不自动付费重算。已有话题的视频观察快照、旧回复、成功请求缓存保留。当前应用继续是本机、单用户、单后端进程。
