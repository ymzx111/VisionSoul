# P037 留空视频自动分析与追问

2026-11-11。Codex 修改本机项目，运行时复用现有本机对白转写和项目配置的 DeepSeek 模型。

> 增加那么多入口会增加主页面的冗余程度，能不能合并一下。当我有手动需求时在对话框输入要求，上传好视频后，点击分析就可以直接处理，这一点已经实现。当我没有手动输入要求时能不能直接识别视频内容，然后根据视频内容处理分析好并给出结果。你怎么看，

> 对，如果没有手动提示和在视频里提取到提示，可以让ai进行追问。就这样吧，你进行界面的代码优化。

- 前端 `MediaChatPanel.jsx`、`media-workflow.mjs`、`chat-workflow.mjs`。沿用同一个输入框和按钮，新视频留空时发送空消息，记录显示“分析这段视频”。
- 后端 `routes/chat.py`、`services/chat.py`、`services/videos.py`、`services/video_tasks.py`、`services/video_reading.py`。仅新视频的普通分析允许空配文。留空时将音画与自动任务提示放进同一次模型调用。可用对白提到题目时沿用现有高清选择上限。保留原转写、证据与话题记录。
- 实际新增模型提示见 [video_auto.md](../backend/app/prompts/video_auto.md)。画面或对白能确定任务就作答，无法确定任务或关键条件就问一个问题。
- 前端验证 `media-workflow.test.mjs`。后端验证 `test_video_chat.py`，覆盖口述读题、无明确任务追问、配文优先、重试去重及无效空消息。模型使用模拟响应，不产生 API 费用。
- 210 项后端测试、76 项前端测试及生产构建通过。手机拍屏素材经临时副本验证，空配文在工作空间一次请求带入转写和 19 张画面，其中 4 张高清，并保存一轮回复。实拍验证使用模拟模型传输，真实模型的答题和追问效果待网页实测。
