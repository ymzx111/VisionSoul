# P103 视频读题完成后自动交付

> 三次视频测试均通过，唯一缺陷是第二次视频再一次出现了分析好视频需要手动确定的问题。修复这个问题，并分析这个问题的处理难点是什么，为什么多次出现，是什么原因。

- 2026-11-16，Codex。实拍 C 最大公约数与最小公倍数题的首轮已读清输入、算法及输出，但模型说「请在下一轮确认即可生成」。更早的冒泡降序视频也出现只复述题意的回复。旧收尾检测只匹配少数源码承诺，且把所有「请确认」一律当作缺项，因此未触发补生成。
- 工作解析的空白视频请求采用模型观察中已识别的编程题信息，并区分单纯确认生成与具体题意缺项。若没有完整源码，复用本轮画面触发最多一次补生成。长视频的视觉复核读清后也能进入这条流程，沿用已有重试预算。真实歧义、缺画面及真实数据授权继续走已有询问与沙盒流程。
- 修改 `backend/app/services/local_ide.py`、`backend/app/services/videos.py`、`backend/app/prompts/video_auto.md`、`tests/test_video_chat.py` 和开发便签。
- 两份保存的只复述或等待同意回复均能识别为漏交付；本次随后生成的真实 C 源码及 3 组样例离线全部通过。模拟模型回归覆盖首轮补生成、视觉复核后补生成和真实歧义不启动编辑器。本轮未调用付费模型。
- 23 项视频对话、16 项视频读题、33 项聊天测试通过。新版工作台已打开，健康接口验证通过。
