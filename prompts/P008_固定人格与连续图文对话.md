## 2. 用户实际指令与确认（原文）

> 继续任务安排

询问固定伙伴的说话风格后，用户选择：

> 活泼俏皮，轻度幽默

此前已确定的约束：单图可预览和分析；多图只预览，提示“目前只能分析单个图像”；模型采用 DeepSeek Flash，以小型可运行 MVP 为优先。

## 3. 实现决策与人格提示

- 伙伴暂用名“小灵”，固定人格标识 xiaoling-v1。
- 实际运行的人格提示全文保存在 `backend/app/prompts/companion.md`，由 `core/persona.py` 读取。
- 规则：活泼、轻度幽默、有自己的观察；严肃/失落情境减少玩笑；不空泛吹捧，不声称真人身份、真实情绪或不存在的长期记忆。
- 图片理解与伙伴对话共用该人格和官方 API 客户端；客户端只能提供用户消息，不能提交 system 角色或替换服务端历史。
- 情绪变化当前是语境化表达规则，不宣称实现情绪识别评分或独立状态机。
- 工作台增加“伙伴对话”模式，左侧图片可选；保留原来的单次图片理解。
- 话题最多关联一张图片；换成另一张时，在发送动作发生时开启新话题。
- 单图未上传成功及多图场景都禁止发送，避免用户以为发送了图而实际只发出文字。
- 历史由后端 SQLite 读取；每轮只提供一张当前话题图片，历史取最近 6 轮完整问答并设文字预算。
- 不自动重试；前端防止并发发送，后端单进程锁防止同话题重复处理；完成请求可按 request_id 恢复。
- 只有整轮成功后才在同一个数据库事务中保存用户消息、伙伴回复和完成请求缓存，失败不留下半轮对话。
- 保存聊天记录是下一步偏好记忆的基础，本轮不自动抽取偏好、不加入跨话题用户画像。

## 6. 本机与真实 API 验证

启动前先在实际图片目录与聊天存储目录进行临时写入检查，再初始化 SQLite；均成功，避免重复 P007 的只读服务问题。

使用自动生成的红色方形/蓝色圆形测试图，在真实工作台发送两轮消息：

第一轮用户测试文字：

> 我叫小夏，今天第一次画出了这两个图形。你看到了什么？请用一句活泼的话回应。

实际回复：

> 小夏，我看到一个红色正方形和一个蓝色圆形并排站着，一个方方正正，一个圆滚滚的，像是刚认识就凑在一块儿的好朋友！

本轮用量 566 token。

第二轮用户测试文字：

> 我刚才说我叫什么？图里右边的图形是什么颜色和形状？请用一句话回答。

实际回复：

> 你叫小夏；图里右边的图形是蓝色的圆形。

本轮用量 601 token，两轮合计 1167 token。昵称为测试虚构值，不是记录用户真实身份。
两次 POST /api/chat/messages 均返回 200，没有为等待页面结果而重复提交付费请求。

重启后端后，直接读取该话题仍有四条消息；浏览器刷新后进入伙伴对话，也恢复了相同内容及图片消息，不触发新的模型调用。
当前桌面窗口 1101×930，整页尺寸同样为 1101×930；对话超过可见区时仅在聊天区内部滚动。
验证结束后只清理了精确记录编号、仍为四条测试消息的虚构话题及其自动生成图片，用户其他话题和原有图片保留。工作台恢复为新话题欢迎页，测试昵称不会留作用户画像。
两轮结果验证了这组测试输入的风格、图像与上下文能力；人格在不同话题下的稳定性仍需后续用户验收和持续评估。

## 7. 限制和下一步

- 当前只面向本机开发，没有账号隔离，不直接对外公开。
- 并发锁针对一个后端工作进程；不在本阶段使用多 worker。
- 上游超时或最终写库失败时，不能保证上游没有用量；不自动重试，已完成且入库的请求可以恢复缓存回复。
- 每段话题列表读取最多最近 200 条消息，近期列表最多二十段；API 上下文最多最近六轮并受字符预算约束。
- 下一阶段：从用户明确表达中保存少量偏好，提供查看、修改和遗忘，再验证跨话题基础记忆。
