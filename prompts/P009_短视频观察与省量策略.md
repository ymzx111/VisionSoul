## 3. 实际运行提示与模块

完整 system 提示保存在 `backend/app/prompts/video.md`，包含实际 JSON 示例、最多 8 条核心观察、去掉相邻重复描述、轻度幽默回应、事实依据与不确定性规则。

user 文本为：

> 请按上述 json 格式分析以下有序视频采样。只观察画面，不包含音频。

随后按顺序添加每张图片前的文本 `帧编号 {index}；采样秒数 {seen_at}` 和该截图的低精度 image_url 内容。时间从本地解码取得，不让模型编造时间，也不传入聊天历史。

- 使用 PyAV 19.0.2 的 Windows wheel，其内含 FFmpeg 库；未安装系统 FFmpeg 或另一套模型 SDK。
- H.264 MP4 默认 60 秒、50 MiB、4K、60 FPS；内容解码校验，不信任文件名和 MIME。
- 本地独立子进程有 45 秒超时、视频时间与帧数限制；禁用外部引用。不解码音频用于模型理解。
- 默认每 3 秒采样，最多 20 次；缩图最长边 768，只合并完全相同的相邻像素画面，保留各个时间点。
- 图片统一 detail=low，合并成一次模型请求；一次同时输出主要事物、摘要和小灵回应。关闭思考，输出上限 1600 token。
- 对模型返回的结构和帧编号做校验，不接受找不到截图的证据编号；结构错误或截断不自动重试。
- 文件内容与抽帧配置确定视频标识，成功结果按模型、提示和预算等配置缓存。刷新、重启、新服务对象和重复上传可读缓存；密钥不参与缓存指纹，也不进入响应。
- 缓存损坏不自动改为付费重算；保存失败明确提示上游可能已计费。
- 并发控制适用于本机单进程；不保证跨进程或进程崩溃时的上游恰好一次计费。

## 6. 当前边界与下一步

不是逐帧完整理解，不分析声音，不保证短暂主体、细小月亮或全部场景都能被采到。输出为主要观察，最多 8 条，不是完整事件日志；时间是依据截图的采样点，不代表精确出现区间。

第一版无视频继续追问、实时视频、长视频、HEVC 转码、自动地点识别、情感诊断、用户画像和多角色。MP4 原文件含原音轨及可能的元数据，仅本地播放；模型只收到静态截图。当前本机存储没有自动删除策略，公开部署前需要访问控制和配额。

下一步优先由用户提供实际体验：天空月亮持续可见、转向湖面，观察是否识别主要事物、顺序是否正确、截图是否对应、小灵是否自然、时间与 token 是否可接受。短暂出现、远处小月亮、高速镜头等单独列为失败样例，根据结果再调整密度/精度，不提前加复杂任务。
