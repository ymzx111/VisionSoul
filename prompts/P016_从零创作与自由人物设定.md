# P016：从零创作与自由人物设定

日期：2026-11-09

## 1. 用户实际 Prompt

> 我们把基础推倒一下，我现在想重新编撰一个角色，所以我不希望有这么多条条框框，你可以将黏贴内容改的简单一点，我去跟一个ai聊好角色背景，可以很自由地导入到对话里。而不像我刚才的看到那样，要限制提示词，限制背景。总之，我希望可以重新从零开始编写一个人物

本次指令优先于之前固定小灵名字、性格和分项 JSON 导入的约定。保留一张卡与多卡存储扩展点，允许重新命名和编写整份人物；不新增角色切换，不清除用户聊天和记忆。

工具：Codex 桌面端修改现有仓库，浏览器使用 computer-use 验证。基于上次尚未提交的 P015 修改继续调整，没有重建仓库或恢复覆盖用户文件。没有真实模型调用。

## 2. 产品变化

- 移除 JSON 导入弹窗、复制格式模板及逐项字符限制的编辑界面。
- 人格页改为“角色名称”和“自由人物设定”大文本框，直接粘贴或写作。
- “从空白开始”建立本地空白编辑稿；保存草稿与生效仍分别操作，空白草稿可存。
- 试说与历史版本收在折叠区域，不要求用户先通过站内 AI 讨论。
- 新设定可用普通文字、Markdown、世界观和对话样例，无须固定章节；不解析、拆分或润色原文。
- 角色名称在文字、视频、图片回复界面动态显示。内部仍用原 `xiaoling` 编号，保持原话题、卡片、记忆兼容。

## 3. 实际提示与数据兼容

`RoleProfile` 新增 `mode`（旧数据默认 legacy）和 `definition`。自由模式只把显示名字和 definition 用于人物编排，不使用遗留 identity/traits/background 等字段；前端保存自由稿时将这些遗留字段置空，防止旧性格暗中混入。旧版卡片与历史版本原样保留并继续可读，未执行破坏性表迁移。

`compile_profile` 自由模式的实际前置提示为：

> 根据用户编写的人物设定扮演角色，显示名称为{名称}。人物的性格、背景、口吻和相处方式以这份设定为准，不额外添加旧角色性格。

之后直接加入 definition 原文。自由模式不再附加旧 companion.md 的语气、段落数、玩笑频率等表达规则。只补充虚构背景与真实用户记忆/画面事实的区别，并在用户明确询问真实系统身份时如实回答。视频任务仍约束观察 JSON 和画面依据，回应风格改为遵循人物设定，不额外指定幽默或追问方式。

自由文本字段关闭全局首尾空格裁剪，保留段落和空格。技术容量为 20000 字符，名字 64 字符；已取消逐项 120/160/200/240 字的创作限制。空白不能发布/试说，避免无内容替换正式人物；草稿可以保存空白。保存与发布继续使用版本冲突保护。

站内设定助手 API 为兼容保留，提示改为自由创作，没有固定名字/身世；主页面不再显示该讨论栏。旧请求结果和聊天不重写。整段自由设定会参与后续模型输入，较长设定相应增加输入量；没有添加每轮自动整理或额外润色调用。
