## 3. 现象与证据

- 页面及 `/health` 可以访问，前端图片上传请求确实到达后端。
- PNG 和 JPG 上传均出现 HTTP 500。
- 日志定位到 `backend/app/services/images.py` 中 `destination.open("xb")`。
- 明确异常为 `PermissionError: [Errno 13] Permission denied`，目标目录是项目的 `backend/storage/images/`。
- 文件已经经过图片校验，失败发生在保存阶段。
- 当时启动的自动工具进程没有所需目录写入授权；能浏览页面不代表能写入图片。

## 4. 处理经过

1. 定位后未重复调用 DeepSeek。
2. 申请图片子目录写入授权，并停止原受限制服务。
3. 之后自动启动工具连续遇到运行环境刷新错误；恢复项目目录授权后仍未能自动启动。
4. 没有改写 Windows 访问控制或尝试绕过限制，改由用户在 PyCharm 项目终端正常启动服务。
5. 用户启动后反馈“测试好了”，确认上传恢复正常；该恢复结果来自用户手动验证，不冒充助手自动验证结果。
6. 收尾时，自动工具尝试结束手动启动的 Python 进程，被 Windows 拒绝；交由用户在原终端按 Ctrl+C。
7. 用户确认已停止，随后检查本地健康接口无法连接，确认 8765 服务已关闭。

## 5. 以后使用的启动和关闭方式

在 PyCharm 项目终端执行：

```powershell
Set-Location G:\VisionSoul\backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

运行后访问 `http://127.0.0.1:8765/app/`。服务终端保持打开。
结束时在该终端按 `Ctrl+C`，确认命令提示符恢复。
关闭网页不会自动关闭服务；服务停止后网页无法访问属于正常状态。

自动工具如需启动服务，必须先具备图片目录写入权限，再验证实际上传和预览，不能只检查网页或健康接口。
如工具无法启动或无法结束用户手动启动的进程，应明确交接给用户，不修改系统权限来规避限制。
